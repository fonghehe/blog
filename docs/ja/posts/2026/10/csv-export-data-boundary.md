連絡先を出力したら、メモが数式になり、長い ID が指数表記になった。サーバーの文字列は変わらず、CSV も解析できるのに、利用者が見る意味は変わっている。出力ではファイル構文と表計算ソフトの自動解釈を別々に考える必要がある。

ここでは ID、名前、メモを扱う。例は疑わしいテキストの CSV 出力を拒否し、文字列型を明示できる形式へ案内する方針だ。すべてのソフトに効く万能なエスケープを提案するものではない。

## 引用符は行と列の境界を守る

カンマ、改行、引用符を含む値は CSV として符号化する。フィールドを引用符で囲み、内部の引用符を二つにすれば、メモが別の列や行になることを防げる。行末には CRLF を使い、ほかの形式を受け入れるかも契約にする。構文は [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180)を参照できる。

ただし、引用符付きの `=1+1` も数式と解釈され得る。引用符は区切りであり、セルの文字列型を宣言しない。[OWASP の説明](https://owasp.org/www-community/attacks/CSV_Injection)では、保存して再び開くと一般的な対策の効果が変わる点も指摘されている。最初に開けただけでは検証は終わらない。

## 列の型と読み手を決める

ID、金額、自由記述、列挙値を区別する。数字だけの ID でも先頭のゼロを保持したい場合がある。金額には精度と通貨が必要で、マイナスから始まる値を一律拒否するテキスト用ルールは使えない。任意のオブジェクトを出す汎用関数より、業務別の出力の方が契約を明確にできる。

人が開く帳票と機械交換用のファイルも分ける。後者は原文の厳密な保持を要求し、前者は明示的な文字列型を必要とする場合がある。単一引用符を付け足す方法は再取り込みの値を変え得る。対象の読み手と形式を、隠れた変換ではなく操作の説明にする。

## 無言で改変せず、例では拒否する

以下は連絡先のテキスト列だけを扱い、代表的な数式の接頭辞と先頭制御文字を拒否する。正当な名前やメモも拒否し得るため、理由と文字列セルを使うワークブック出力を提供する。全ソフト、地域設定、再保存の挙動を網羅する検出器ではない。

```javascript
export function csvTextCell(value) {
  const text = String(value ?? '');
  if (/^[\s\uFEFF]*[=+\-@]/u.test(text) || /^[\t\r\n]/u.test(text)) {
    throw new Error('text requires a typed spreadsheet export');
  }
  return '"' + text.replaceAll('"', '""') + '"';
}

export function exportContacts(rows) {
  const header = ['id', 'name', 'note'].map(csvTextCell).join(',');
  return [header, ...rows.map(row =>
    [row.id, row.name, row.note].map(csvTextCell).join(',')
  )].join('\r\n') + '\r\n';
}
```

成功させるために先頭文字を削除しない。プラス、改行、負数のような ID が原文にあるかもしれない。許可リストや接頭辞で表現を変えるなら、その変更を明示し、再取り込みで原文と混同しない。ワークブックでも、拡張子だけでなく実際のセル型を確認する。

## 符号化と権限も出力経路の一部

UTF-8 BOM は一部のソフトで符号化の認識を助けるが、数式の防止や ID 保持の保証にはならない。中国語、日本語、引用符、複数行を対象環境で確認する。列名、列挙値の翻訳、日付形式も安定させる。

出力 API は権限と絞り込みを再検証する。一覧の一部が読めたことは全件出力の権限を意味しない。長時間の処理はジョブ状態と管理されたダウンロード先を返し、生成条件と列定義の版を記録する。障害ログへ個人のメモ全文をコピーしない。

## 往復と再保存で検証する

通常文、カンマ、引用符、改行、先頭ゼロ、長い数字、数式接頭辞、制御文字を固定の資料にする。パーサーの往復、アプリの拒否経路、対象ソフトでの初回表示と保存後の再表示を確かめる。

列ごとに型、許容する変換、読み手を残しておく。自由記述列を追加するとき、その契約が汎用エスケープ関数より早く問題を知らせてくれる。
