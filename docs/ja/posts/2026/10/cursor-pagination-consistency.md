問い合わせ一覧を二ページ読み込んだ後、先頭に一件追加される。続きを取得すると、前ページの最後の項目が再び現れる。重複を消せば表示は整うが、削除やソートキーの変更による欠落までは直らない。ページングには、まず「続き」の定義が必要だ。

作成日時の降順で並ぶ一覧を設計例として考える。実際の障害報告ではなく、重複のない表示を完全性の証拠としないための検討である。

## ページ番号は位置、カーソルは境界を表す

一ページ二件で A、B、C、D の順に並ぶとする。A、B を読んだ後で先頭に X が入ると、`OFFSET 2` は B、C を返す。逆に A が削除されると、次のページが D から始まり、C を飛ばす可能性がある。変化する集合では位置が動いてしまう。

最後の項目のキーをカーソルに含めても、作成日時だけでは同時刻の複数レコードを区別できない。`(created_at, id)` で一意の順序を作り、対応するインデックスを用意する。NULL を許す場合も配置を明示し、SQL の比較結果に暗黙の仕様を任せない。

## 一件余分に取得して次ページの有無を決める

以下は続きの取得用で、初回はカーソル条件を外す。表示が 20 件なら 21 件取得し、余分な一件で継続の有無を判断する。次のカーソルには表示した 20 件目を使う。捨てた 21 件目を使うと一件欠落する。[PostgreSQL の行比較](https://www.postgresql.org/docs/18/functions-comparisons.html)と [LIMIT/OFFSET](https://www.postgresql.org/docs/18/queries-limit.html)が基本の参照資料になる。

```sql
-- $1: tenant, $2: cursor created_at, $3: cursor id
SELECT id, created_at, title
FROM tickets
WHERE tenant_id = $1
  AND (created_at, id) < ($2, $3)
ORDER BY created_at DESC, id DESC
LIMIT 21;
```

```javascript
export function appendPage(current, incoming) {
  const byId = new Map(current.map(row => [row.id, row]));
  for (const row of incoming) byId.set(row.id, row);
  return [...byId.values()];
}
```

このマージ関数が扱うのは重なりだけだ。既存の表示位置を保ち、同じ ID の内容を更新する。変更された値で並び順も変えるなら、その方針を別途決める。サーバー順を保証すると説明しつつ、クライアントだけ別のキーで再ソートしてはいけない。

## カーソルと検索条件を結び付ける

未対応から全件へフィルターを変えたら、以前のカーソルは使えない。テナント、条件の要約、ソート方式の版、末尾キーを不透明なカーソルにまとめる。Base64 は符号化であって改ざん防止ではない。必要なら署名を検証するかサーバー側の状態を参照する。権限確認は毎回独立して実行する。

フロントエンドは正規化した条件から検索キーを作り、変更時にページ列とリクエスト世代を更新する。キャンセルだけでは、既に届いた応答を防げない。反映直前にも世代を確認し、異なる条件の結果を連結しない。キャッシュもページ番号だけでなく検索の識別情報に属する。

## 境界が安定しても同じ集合とは限らない

不変の作成日時を使えば、先頭への追加による位置のずれは避けられる。一方、優先度など変更可能なキーでは、項目が境界をまたぎ、重複したり、既読領域に移って一度も表示されなかったりする。受け取っていない項目を重複排除で復元することはできない。

リアルタイム一覧なら新着を通知し、利用者の更新操作で境界を作り直す設計が可能だ。監査用の出力ならサーバースナップショット、結果の実体化、整合性を管理した読み取りが必要になる。`asOf` 条件だけでは、過去のレコードの更新や削除までは固定されない。

## 境界をまたぐ変更を固定の手順で検証する

同時刻の項目、ページ間の追加と削除、ソートキー変更、条件変更後に届く古い応答を試す。画面では ID と世代、API では順序と次カーソル、スナップショットでは集合全体の完全性を確認する。

初期集合、変更操作、各応答を具体的なテストデータにする。「何度かスクロールできた」だけでは欠落を見落とす。どの変化を許容し、どこで再読み込みを要求するかを、このデータから決めておく。
