ニューヨークの毎週月曜九時と、168 時間ごとの実行は同じではない。夏時間をまたぐと、最初の UTC 値だけを保存した予定は一時間ずれることがある。書式設定の不具合に見えても、原因は利用者の意図を保存していないことにある。

予約、請求日、終日の休日を、意味の曖昧な timestamp 一つで扱わない。現地の時計を保つのか、時間線上の一定間隔を保つのかを先に決める。

## 三種類の時間には別のモデルを使う

発生済みの監査イベントは `Z` 付き ISO 文字列などの明確な瞬間で保存できる。誕生日や終日の休日は日付であり、特定地域の午前零時へ無理に変換する必要はない。将来の現地予約には、現地日時と IANA のゾーン識別子が必要だ。確認後は解決した瞬間とオフセットも残すと、その判断を説明できる。

UTC+8 の固定オフセットは、地域の時刻規則そのものではない。規則は変わるため、将来の予定を新しい規則に追従させるかを決める。[Temporal のタイムゾーン資料](https://tc39.es/proposal-temporal/docs/timezone.html)は時計上の時刻と正確な瞬間を区別している。ここではその考え方を使い、特定版の Temporal がブラウザーにあるとは仮定しない。

## 同じ現地時刻が二度現れる

以下の二つの UTC 値は、ニューヨークではどちらも 2026 年 11 月 1 日の 01:30 と表示される。一時間違っていても、オフセットを省くと同じに見える。検証コードは `Intl.DateTimeFormat` だけに依存する。

```javascript
export function formatMeeting(instant, timeZone, locale = 'en-GB') {
  return new Intl.DateTimeFormat(locale, {
    timeZone,
    dateStyle: 'medium',
    timeStyle: 'short',
  }).format(new Date(instant));
}

const first = '2026-11-01T05:30:00Z';
const second = '2026-11-01T06:30:00Z';
const zone = 'America/New_York';
console.assert(formatMeeting(first, zone) === formatMeeting(second, zone));
console.assert(new Date(first).getTime() !== new Date(second).getTime());
```

重複する時刻は早い方と遅い方を選べるようにし、対応するオフセットを確認画面で示す。春には存在しない現地時刻もある。02:30 を無言で 03:30 にずらせば予約内容を変えてしまう。再入力を求めるか、明示的な調整方針を提供する必要がある。

## フォームの現地日時には地域が含まれない

`datetime-local` は日付と時計の値を表すが、地域のゾーンを決定しない。端末設定に依存する解析へ渡すと、端末ごとに別の瞬間になる。現地日時、ゾーン、曖昧さの処理方法を明示してサーバーへ送り、一つの規則で解決した結果を確認する。

失敗時も入力を保持し、利用者が選択を修正できるようにする。上海から東京へ移動しても、ニューヨークの会議の意味は変わらない。閲覧者の現地時間を併記しても、予約の所属ゾーンを上書きしない。「表示ゾーンを変える」と「別地域の九時へ移す」も編集画面で区別する。

## 繰り返しは次回の結果ではなく規則を保存する

現地時刻での毎週予約には、曜日、時分、地域、欠落と重複への方針を保存する。次回は日暦を進めてからゾーンで解決する。前回の UTC 値に七日分のミリ秒を足す方法は一定の経過時間を保つモデルであり、監視ジョブには適しても会議とは意味が異なる。

時刻データベース更新で将来の結果が変わる場合は、規則の版や解決記録を保存し、未発生分を方針に沿って再計算し、影響を説明する。発生済みの監査事実は変更しない。UTC しか受け付けない連携先には、一回分の展開結果であることを示し、そこから繰り返し規則を逆算しない。

## 書式より境界を検証する

重複時刻、存在しない時刻、年越し、三十分単位のオフセット、端末ゾーン変更、サーバーと端末の規則差を試す。解決した瞬間と、再表示した際の日付・時計値の両方を確認する。終日予定は地域を変えて閲覧しても前日に移らないことを検証する。

「現地九時を保つ」か「一定間隔を保つ」かを API と画面の説明に書く。その判断を先に共有すれば、次の時計変更時に原因不明の予定ずれを追う必要がなくなる。
