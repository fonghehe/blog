頁面看起來「滑不順」，不應該立刻給所有 Widget 加 `const`。Flutter 的卡頓可能發生在 Dart 構建階段，也可能出現在圖片解碼或光柵化階段；兩者的修復方向不同。

## 用可復現路徑採樣

在真機 profile 模式下，固定頁面、數據集和手勢路徑；記錄慢幀出現的時間點。先看幀時間線里 UI 與 raster 的耗時，再把慢幀與當時的頁面操作對應起來。熱重載、調試斷點和首次著色器準備都可能改變測量結果，不能用一次偶發峰值下結論。

若 UI 線程耗時高，檢查是否在 `build` 中解析 JSON、排序大數組，或讓頂層狀態變化重建整棵列表。把計算移到數據層，縮小監聽範圍，並使用 `ListView.builder` 按需建立行。若 raster 耗時高，檢查大圖尺寸、模糊陰影、頻繁裁剪和重複離屏繪制；優先減少實際繪制工作。

## 優化要有前後對照

每次只改一個因素，記錄同設備上的慢幀數量、峰值耗時和記憶體。某個修復使平均幀更快，但導致列表圖片重新載入，也不算成功。最後在低端設備、深色模式和字體放大場景再跑同一路徑。
