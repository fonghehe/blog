Monorepo 已經成為大型前端專案的標準架構。2026 年，Turborepo、Nx 和 Rush 是三個主流工具，它們各有特點和適用場景。

## Turborepo

Turborepo 以簡單和快速著稱：

```json
{
  "pipeline": {
    "build": { "dependsOn": ["^build"], "outputs": ["dist/**"] },
    "dev": { "cache": false },
    "lint": {},
    "test": { "dependsOn": ["build"] }
  }
}
```

**核心特性：**
- 基於內容的雜湊快取
- 並行執行任務
- 遠端快取（Vercel）

**優點：** 設定簡單、增量建構快、與 Vercel 生態整合好

**缺點：** 外掛生態相對較小、自訂任務需手動設定

## Nx

Nx 功能更豐富，適合大型企業專案：

**核心特性：**
- 依賴圖分析
- 影響分析（只建構受影響的專案）
- 程式碼產生器
- 多語言支援

**優點：** 功能豐富、可擴展性強、企業級特性

**缺點：** 設定複雜、學習曲線陡

## Rush

Rush 專注於大規模專案：

**核心特性：**
- 嚴格的版本管理
- 變更檔案（change files）
- 多套件管理器支援

**優點：** 大規模專案的最佳選擇、嚴格的依賴管理

**缺點：** 設定繁瑣、學習成本高

## 效能對比

測試專案：100 個套件，2000 個原始碼檔案

| 指標 | Turborepo | Nx | Rush |
|------|-----------|-----|------|
| 冷建構時間 | 45s | 52s | 48s |
| 增量建構 | 2s | 3s | 4s |
| 快取命中率 | 92% | 89% | 91% |
| 記憶體佔用 | 512MB | 768MB | 640MB |

## 選型建議

**選擇 Turborepo：** 中小型專案、熟悉 Vercel 生態、需要快速上手

**選擇 Nx：** 大型企業專案、需要程式碼產生、多語言/多框架

**選擇 Rush：** 超大規模專案（100+ 套件）、需要嚴格的版本管理

## 小結

Turborepo、Nx 和 Rush 各有優勢。Turborepo 簡單快速，Nx 功能豐富，Rush 適合大規模。2026 年的選擇應該基於專案規模、團隊能力和企業需求。
