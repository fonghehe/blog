移動端會話問題常在「重新打開應用」後才暴露：舊帳號的快取短暫閃現，多個請求同時更新權杖，或使用者登出後背景回呼又把舊憑證寫回來。解決它需要把憑證生命週期與業務資料生命週期一起設計。

## 明確存放與邊界

敏感權杖放在平台安全儲存能力中；普通業務快取應按使用者 ID 分區，不能僅以介面路徑作為鍵。不要把權杖寫進記錄、深鏈或可被其他應用讀取的明文文件。啟動時先恢復會話並確認使用者身份，再顯示該使用者的私有快取。

## 更新只允許一個進行中

權杖將過期時，多個請求共享同一個更新 Promise / Future；更新成功後繼續請求。若伺服器端拒絕更新，統一失效會話並取消待發送請求，不能讓每個頁面各自彈一次登入框。登出時遞增會話世代：所有帶舊世代的非同步響應即使晚到，也不得寫入新帳戶狀態。

```text
session A, epoch 7 → 發出請求
使用者登出 / 切換帳戶 → epoch 8，清理 A 私有快取
舊請求回傳 → epoch 不匹配，丟棄響應
```

驗證時覆蓋強制關閉應用重啟、時鐘偏差、並行 401、離線登出與快速切換帳號。客戶端防護不能代替伺服器端對每個請求的權限檢查。
