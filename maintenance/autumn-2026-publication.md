## 使用脚本

先预览：

```sh
node scripts/publish-2026-autumn.mjs --dry-run
```

确认计划后执行本地提交：

```sh
node scripts/publish-2026-autumn.mjs --apply
```

默认不提交；脚本不推送。实际执行时，同题五种语言和对应的站点计数一起提交；作者与提交者时间均采用计划时间。每次提交晚于文章约 7 至 29 分钟，且在同一天。已有提交历史不被改写，因此补记的历史时间可能早于其父提交。

执行前不要先把新文章加入暂存区或整体提交，否则会触发暂存检查或被判定为已提交。脚本、清单、测试与本说明可以随后单独作为工具提交。脚本拒绝未完成的暂存修改、无关的已跟踪修改、正文哈希变更、部分语言已提交等状态。已完整提交且内容匹配的选题会跳过，可在排除失败原因后重新运行。

文章哈希冻结了当前审核版本。如需改文，先重新校验五语、元数据、排期和构建，再更新清单中对应文件的 SHA-256；脚本不会自行接受正文变化。

脚本用临时快照和独立索引逐篇计算计数，避免尚未提交的后续文章提前进入历史计数。执行期间避免其他 Git 写操作。异常中止后查看 git status；已成功的提交会保留，未来文章仍在工作目录。

## 选题与翻译边界

选题已检索既有简体文章标题，并对相关正文抽查。新内容聚焦以往未成专题的具体问题；例如 Unicode 坐标区别于国际化库入门，大文件流式下载区别于 Node 上传，SSE 分帧区别于 SSR 流式渲染。没有把旧文章改标题重发。

五语采用相同章节、代码、引用来源和技术结论；繁体版本基于同一中文正文转换并调整地区用语，英文和日文按相同论证翻译。各语言阅读时间由仓库脚本实际计算，未人为加长。例子是设计演练，不虚构线上事故、生产指标或亲历项目。

文章引用官方标准或项目资料。SSE 示例明确限定为 LF/CRLF、data-only 子协议；摄像头、IME、文件选择器的真实平台行为仍需按文章给出的设备验收路径验证。SQL 为接口设计示例，未连接数据库执行。
